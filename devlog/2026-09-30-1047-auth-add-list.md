# Enroll Agent Credentials Through One Verb

Work unit #1638: `freesided auth add` and `auth list`, built on the
admitted-agent contract (#894). This note records the owner's choice to ship
Claude enrollment without a provider check, and the trust-boundary decisions
the credential paths needed.

## Owner Decision: Ship Claude Add Without a Provider Probe

The plan checked a Claude setup token with `claude auth status --json` in a
networkless ward container. That check proves nothing: the pinned CLI reports
`loggedIn: true` for any token-shaped value, because it inspects only local
state. The owner chose to defer a real check rather than hold the unit.

- **Shipped:** stdin-only token capture, a shape check (length bounds,
  printable ASCII, the `sk-ant-oat` setup-token prefix, which refuses the
  likeliest wrong paste, an API key), volume authoring, and the
  `setup_token` manifest proof preflight already runs.
- **Deferred (#1647):** a ward-proxied `claude -p` probe that spends one minimal
  request through the ward's network path. A bad or revoked token meanwhile fails
  closed at its first run, which costs one failed stage, not a wrong grant.
- **Rejected: keep `claude auth status`.** A check that always passes would
  read as verification in the PR and the enrollment record while proving
  nothing.

## Claude Enrollment Has No Journal or Recovery Item

Codex enrollment spends a refresh token, so a crash between spend and record
must be recoverable: it keeps the re-enrollment journal and marker item.
Claude enrollment spends nothing. Authoring a fresh volume is repeatable, so a
failed attempt deletes the volume it created and a rerun retries.

- **Rejected: reuse the Codex journal for Claude.** Its marker item blocks the
  identity as "Codex re-enrollment required", which would be false for a
  Claude identity and would demand a recovery action with nothing to recover.
- **A failed bootstrap stays retryable.** Identity, enrollment, and the bound
  lease are recorded in one transaction before any volume exists. An
  identical enrollment with no generation is accepted on retry; one with a
  generation, or with different fields, refuses as an existing enrollment.
  Refusing the generation-less case would strand the client with a recorded
  enrollment and no way to add its store.

## Trust Boundaries

- **The token never enters argv, env, labels, or errors.** It reaches the
  volume only through a staged owner-only file copied by the networkless
  exporter-image seeder, the same handshake the prompt volume uses. The
  wrapper type renders a fixed placeholder for every fmt verb and JSON, and
  every error on the token path is a fixed string.
- **Never author over a volume this command did not create.** An existing
  volume may hold another identity's live credential, so it refuses, and
  cleanup deletes only what this run created. The volume carries no handoff
  labels, so run-scoped recovery never reaps it.
- **Account binding is an operator attestation for Claude.** The pinned CLI
  exposes no account identity. For Codex it comes from the login's
  `tokens.account_id`, and a login without one refuses.
- **The store re-gates on read.** `auth list` reconstructs every identity and
  enrollment through the same account-binding checks that gate writes, so a
  tampered row refuses the listing instead of rendering. The label masks the
  binding to its last four characters behind a fixed-width mask.

## Refute-First Findings

An independent reviewer tried to break the Claude and Codex paths.

- **Confirmed, fixed: check the volume before recording.** `auth add` named
  at an existing volume used to record the identity first, then refuse. The
  interim volume is a fixed binding with no identity delete, so that left a
  permanent, enabled identity pointing at another identity's store. The
  existence check now runs before anything is recorded, and again under the
  lease. PR review found the same shape for a name over the runtime's 64-byte
  limit, which create refused only after the binding was recorded, and for an
  exporter image without a digest pin; both are now checked before recording.
- **Confirmed, fixed: a failed first inspection kept the volume.** A volume
  this run created and then could not inspect was never deleted, so every
  retry refused it as existing. It now takes the same cleanup path as other
  failures, and a failed delete tells the operator to remove the volume by
  hand and rerun with the same name.
- **Declined: an ownership label on the volume before delete.** A foreign
  volume would have to appear between the list and the create while the
  create still succeeds on that name. No reachable path was shown; whether
  the runtime's create refuses an existing name is unverified.
- **Allowed: a hard kill can leave the staged token.** SIGKILL between
  staging and cleanup leaves a 0600 file in a 0700 directory under the
  per-user temporary directory. SIGINT and SIGTERM clean up.
- **Disproved by check:** no token reaches argv, env, labels, errors, or
  output; `enroll-codex` with no enrollment is unchanged; the Codex
  generation append shares the verify transaction, so it adds no
  unrecoverable spent-token state; `auth list` re-gates every row.

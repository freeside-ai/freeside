# Name Tasks After Durable Dispatch

The task namer runs in the daemon after specification or production dispatch.
It does not run in the one-shot submit process. The daemon already owns the
inference client, shared judgment budgets, and research fetcher; adding a second
judgment caller at intake would require coordinating those budgets across
processes. Operator headings are stored in the submit transaction, so those
tasks never need the namer.

Durable dispatch now enqueues naming on a 32-entry in-memory FIFO without
waiting. One worker runs beside reconciliation; `Engine.Run` cancels and joins
it before returning. Saturation logs an advisory warning and leaves the
identifier fallback, as does a restart that loses queued work. A serial worker
matches the inference client's single in-flight call per site. No persistent
queue or attempted marker is added.

This changes the implementation plan's synchronous call after dispatch.
Review traced a reachable slow provider through that call: each 30-second
timeout held the reconciliation lock and delayed completion acceptance and
every later lane. That evidence invalidated the synchronous choice under
`Reconcile`'s nonblocking contract. A gated-driver regression confirms both
completion acceptance and approval advance while naming waits. Cancellation
joins the worker, and a late result cannot replace an operator or approved
specification name.

The shared Claude adapter still permits only one native call, preserving the
subscription bound recorded in `2026-09-09-2145-subscription-judgments.md`.
Moving naming off reconciliation exposed another path: a namer could occupy
that slot while publication requested adjudication, whose unavailable result
parks review. A validated classifier or adjudicator now preempts naming and
waits for its process and private-directory cleanup before taking the slot.
Only one caller may reserve that handoff, and its own deadline bounds waiting.
Canceling a waiter clears its reservation without freeing a still-cleaning
call. Naming and overlapping workflow judgments otherwise retain immediate
refusal. Unsupported, invalid, or already-canceled requests cannot preempt.
This replaces global collision refusal for naming alone; a second driver or
parallel native calls would violate the existing subscription bound.

Label intake remains coordinates-only. The namer fetches issue text through
the existing research boundary under the run's allowlist and response limit.
The URL uses the stored numeric repository ID and issue number, so a transfer
or reused display repository name cannot redirect naming. GitHub's
`/repositories/{id}/issues/{number}` route was verified live to return the
expected issue directly with HTTP 200; it is observed behavior, not a
documented endpoint guarantee. If that route becomes unavailable, naming
retains the identifier fallback. The research origin remains
`https://api.github.com`, with the same policy checks and no allowlist widening.
It sends only the declared source fields to inference and retains a
producer-labeled advisory claim before storing the name. The input prefix
budget accounts for JSON escaping. Fetch or inference failure leaves the
identifier name and does not undo dispatch.

The first accepted specification may refine an agent name or name an identifier
fallback. The store allows
agent-over-agent replacement, while the engine limits refinement to acceptance
without a prior specification artifact. Operator and approved specification
names remain permanent. Approval still takes the name from the approved body's
heading, because that text is digest-bound to the approval; the separate title
field is advisory. The prompt asks for matching title and heading text.

The assigned #1208 Objective and Acceptance explicitly permit naming the
identifier fallback at first specification acceptance. Its implementation plan
keeps that rule. This conflicts with `docs/plan.md`'s task-name lifecycle
paragraph, which defers the identifier's first name until approval. This unit
follows the owner-selected issue contract. Follow-up: #1327 reconciles that
older plan text through a separate document-gated change.

Operator and approved-specification headings are truncated to 60 Unicode runes
for task display, with trailing whitespace trimmed after truncation. Keeping
the heading's source preserves operator precedence and approval timing; dropping
an oversized operator heading would incorrectly let the namer replace it.
The commit-title parser remains separate and unchanged.

## Boundary Checks

Invalid, multiline, oversized, and credential-shaped model names fall back
without creating a name claim. A specifier title longer than 60 characters is
ignored for naming without rejecting the specification. A delayed namer result
rechecks the stored source in its write transaction and cannot replace a name
chosen while inference was running. Naming changes presentation versions, never
the attention item's decision binding.

Independent review and the large-source fixture found that the specification
body reader's 64 KiB limit rejected otherwise admissible naming inputs before
truncation. The namer instead reuses the execution-artifact reader: it verifies
the complete digest within the existing 4 MiB artifact limit, then truncates
only the outbound evidence. The same rule covers research envelopes, whose
base64 body can exceed 64 KiB even for a smaller fetched response. Call-path
review also confirmed that source precedence and the research policy recheck
hold on recovery.

Review confirmed that an admitted long heading could permanently inflate task
and card responses. Regression cases cover exact-bound Unicode, oversized
Unicode, and whitespace at the truncation boundary for both submission and
approval. The proposed source-bytes mismatch was disproved by caller tracing:
the sole production caller passes the same buffer it hashes, writes to the
blob store, and registers as the source artifact. No extra digest guard is
needed at this internal call.

A separate review finding identified a real repository-identity gap: intake
verifies the numeric identity when observed, but a held task can dispatch after
the repository name is reused. The numeric URL fixes that gap without a second,
potentially stale name-to-ID research observation. A regression makes the old
name return unrelated issue text while numeric repository 42, issue 7, still
returns the admitted subject. Fetch failure, research-only storage, and the
existing no-content-in-intake checks remain covered.

Independent refutation checked the preemption reservation against overlapping
callers and canceled waiters. The old call closes its completion signal under
the slot mutex after process reaping and private-directory cleanup, so its
release cannot clear a successor's slot. Actual-adapter regressions verify
classifier and adjudicator success only after the old process and scratch are
gone. Deterministic delayed-cleanup tests disprove early reuse after waiter
expiry; rejected-request tests confirm that invalid calls leave naming alive.

## Revisit When

Revisit queue capacity or recovery if advisory naming regularly saturates the
queue, or if task-name history adds a persisted attempt record. This unit
intentionally adds no migration or durable namer-attempt marker.

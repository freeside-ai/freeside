# Wave Tracker Authority

Chose the single open pinned issue titled `Wave N (...) tracking` as the
authority for Freeside's current phase, wave, and active implementation front
because the spine already replaces that tracker at wave boundaries and its
required Implementation order digest already carries the startable work.
The title identifies the wave and internal exit, while the matching Section 11
roadmap row supplies the phase and shape. Requiring exactly one match makes an
invalid planning state visible to the human instead of inviting an agent to
guess which status claim is newest.

Rejected the plan front matter as the authority because it duplicates a
forge-maintained transition without carrying the active front. Rejected a
generated status file or local ledger because it would add a second tracker.
Rejected derivation from git history or milestones alone because neither
records the active implementation front, and the milestone and tracker update
are coherent only as one spine-owned planning operation.

Historical decision notes remain evidence for how a status was reached, not
sources of live status.

Revisit when wave planning legitimately requires zero or multiple open pinned
issues titled `Wave N (...) tracking`, or when Freeside itself begins serving
authoritative workflow status.

## Keep Publisher Authority and Explain Template Conflicts

Chose an explicit author-fragment contract over relaxing the screen, stripping
trusted templates, or changing publisher formats. The author keeps applicable
Why, What, Screenshots, and Review Notes content. The publisher alone appends
verified evidence, approved source references, disposition history, advisories,
scope decisions, and identity markers. A conflicting template requirement must
be described in safe visible body prose, since stored reviewer notes are not
rendered. This is a material prompt/output-contract clarification.

The public gh-imgup template fixture is `.github/pull_request_template.md` at
`5ad83e9b8e7fe096af323128d7af6d1d4020cfcc`. It requires a reserved check heading
and closing directives; copying either is rejected. Its requested status-prefix
format also differs from the publisher's fixed evidence renderer. The fixture
proves conflicting inputs, not what the discarded live answer contained.

## Screen Before Audit Storage and Again Before Rendering

Chose one shared deterministic screen over a second inference-only screen.
The old inference validator missed Markdown-spliced secrets and reserved
sections that the engine rejected after an audit sample could already be saved.
The shared screen runs before sampling and still runs on reconstructed stored
artifacts. Accepted-answer audit cadence, retention, and the independent
boolean closure site retain their existing behavior.

The planned dependency on publish exposed a test import cycle through signet,
ward, and inference. The issue's scope was revised before extracting the existing
pure candidate-body validator and its marker/budget constants into publicationtext.
Publisher delegates and constant aliases preserve section ownership, byte budgets,
and rendered formats. No test or assertion was bypassed to resolve the cycle.

## Fixed Diagnostics Preserve Rejected-Content Privacy

Refusals identify the first fixed field in title, body, outcome_summary,
reviewer_notes order and its failing screen. Schema failures name no field.
The candidate-body category explicitly covers both size and reserved sections;
it does not mislabel a body-budget refusal as a heading. Only the explain site's
private classified error carries a diagnostic through Client.Call. Arbitrary
validator, decoder, and provider errors retain generic fallback behavior.
Checkpoint Reason carries the safe diagnostic without a schema or key change.
Unclassified author-input, call, and artifact-construction errors use fixed
messages instead of interpolating nested errors.

- Confirmed and fixed: a schema-valid Markdown-spliced synthetic token could
  enter an audit before the old engine screen refused it. Audit-due regression
  calls now reject all four text fields before storage; accepted calls are
  still sampled after a rejection.
- Disproved by differential check: moving the screen, candidate validator, or
  renderer helpers relaxes validation or changes publication bytes. Reconstructed
  the originals from `785980351110efdee2dcb20c45144a67655679df`; 61,956 screen
  decisions, 10,326 candidate validation results (including exact errors), and
  10,326 rendered title/body pairs matched over adversarial and generated inputs.
  The comparison is a session-only scratch check, not a duplicate maintained screen.
- Disproved by focused tests: refused fields or nested errors leak through safe
  diagnostics or advisory samples. Secret, schema, control, bound, directive,
  reserved-section, and arbitrary-provider/validator cases exercise these paths.
- Independent review found no blocking regression in the original extraction
  or the subsequent candidate-validator extraction. It checked the audit ordering,
  fixed diagnostic carrier, budgets, predicates, and dependency graph.
- Preserved policy limit: a markerless disposition-history heading is accepted
  by the old predicate. The prompt prohibits it, but this extraction deliberately
  preserves the accepted set. Tightening that screen is tracked in [#1533](https://github.com/freeside-ai/freeside/issues/1533).

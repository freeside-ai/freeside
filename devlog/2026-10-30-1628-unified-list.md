# Unified List

#2444 folds the Inbox and Tasks views into one list from the 30 Oct
handoff (`docs/design/handoff-2026-10-30-unified-list/`). This note records
what the handoff left to judgment; the gate answers are in
`2026-10-30-1427-unified-list-gate-answers.md`.

## The List Is a Projection, Not a Store

Chose a pure `UnifiedList` value built from the store's snapshots and the
synced tasks over teaching `InboxStore` about tasks, because grouping,
section membership and selection all follow from those two inputs, and the
value tests without a view. The store keeps only what it owned: the
snapshots and the project filter.

The filter needs the task projects to repair itself, since a project that
only a task names is a valid choice in the union the popover offers. So
`SyncCoordinator` hands the store a `taskProjectsProvider`, outside the
unit's declared paths.

## Selection Is a Destination

Chose `NavigationModel.path` typed `[Destination]` over the `[String]` it
held, because a row is now a task or an item, and a bare id made the
difference implicit. `.task` is a kept selection, not a push: when a task's
last open item resolves, `repairSelection` rewrites the item selection to
the task, so the operator stays on it and the detail shows the timeline. A
resolved scoped item is already a row in Finished, so it needs no rewrite.

Repair runs on change events and only against a loaded store. Against an
unloaded one, a cold launch would read a finished selection as gone.

Chose to leave a selected Working task on its timeline when a new item
arrives, over flipping the detail to the new card, because the arrival
shouldn't replace what the operator is reading. The row then sits in Needs
you showing the timeline, and the timeline's own link opens the card.

A snoozed proposal's item leaves the snapshot, so nothing can name its task
afterward and the selection clears, as it does today.

## Working Keywords Keep Bad News

Chose to turn only the `In Progress` status into a stage gerund, over the
handoff's every-row gerund, because a failed or stopped run under a live
task would otherwise read as `Implementing`. `Queued` and `On Hold` become
`Parked`. Any other status keeps its own word.

## Rows Say Round, Not Run

Chose the existing `rowContext` (`Round n`) over the canvas's `Run N`, since
`run_ids` has no documented order and a run count would be a guess.

## Rows Trail a Bare Time

Chose `42m` over the old task row's `42m ago`, as the canvas draws, because
one list had two grammars otherwise. VoiceOver keeps the labelled sentence.

## A Filter Yields to a Routed Selection

Chose to clear a project filter that hides a selection arriving from a link
or a task reference, over leaving the detail open beside a list that doesn't
show it. The other way round, an operator choosing a filter that hides the
selection clears the selection, since that choice came last.

A section the selection sits in stays collapsed, because the operator's
disclosure is theirs. The exception is New Task, which opens Working: the
operator just made that row and expects to see it.

## The Summary Counts Rows

Chose the list's rows for the detail pane's counts, over its item count,
because the contract says rows everywhere and the pane sits beside the
sidebar. The statement changes to `3 need you`, since `1 open item` would be
false for a task holding two.

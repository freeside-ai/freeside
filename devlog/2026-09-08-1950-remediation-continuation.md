# Bind Remediation Continuations to an Approved Recheck Dispute

Chose approve on the recheck's review dispute over a new action or treating
`rerun_trust_evaluation` as producer authority. The existing action and card
facts already work in both clients. The accepted approve command names one
new successor cycle; replay cannot grant another. The owner extended the
narrow #1213 serialization exception to this contract unit.

Chose a successor origin over a parallel publication-authority hierarchy.
Version 1 feedback rows retain their canonical bytes. A continuation's first
producer answers the recheck's findings round, one below its review floor;
later producers follow the ordinary floor. The store authenticates the
accepted commands, resolved dispute, source task, review, adjudication and
reevaluation completion and terminal records before trusting the authority.
The new successor and remediation intent commit together. The original task
and earlier successor tasks stay immutable.

The existing successor-recheck fixture disproved the plan's assumption that
every completed cycle has a ready binding. A verification-blocked successor
has a dispatched task but has never published. Chose to preserve its sealed
place in the chain and derive the update target from the last actually
published ancestor. The owner explicitly chose an acknowledgment-only refusal
when no PR has ever existed, rather than authorizing first publication.
Completion after acceptance and undeliverable remediation input also leave
durable refusals without a producer.

Fresh verification is keyed to the continuation. Its first remediation reads
the source tree from the recheck's checkpoint, not the predecessor's older
verification. Subsequent remediation uses the continuation's checkpoint.
Review rounds still consume the same run-wide budget, and publication uses
the existing owned-PR update capability with an exact expected-old-head lease.

Independent refutation confirmed three defects in the first implementation:
mixed remediation/defer/decline routes lost their non-remediation dispositions;
oversized input escaped as a lane-fatal error; and later successor reads did
not reauthenticate the recheck terminal. The shared disposition writer,
command-bound refusal path and store terminal gate address those reachable
cases. Verification evidence is recorded in the PR.

An upgrade must also repair open disputes retained by the previous release,
whose completed rechecks no longer appear in the pending task scan. Reconcile
those offers from authenticated completion, source, review and adjudication
records, advancing the card version once. Resolved decisions stay closed;
stale commands cannot approve the revised surface.
Independent refutation caught revision churn from no-op repair transactions;
those paths now roll back instead of committing a client-visible revision.

Revisit when a continuation needs first-publication authority, a changed
specification, different policy, or a new review budget. Those need separate
authority rather than being inferred from approve.

# Rehearse on One Fixture Repository

Work unit: #2247. Owner decisions of 2026-10-23, from the rehearsal
discussion after the gh-imgup#125 exit run, recorded because they would
otherwise exist only in chat. Revises
`2026-10-22-1346-rehearsal-real-models.md`.

## The Split

Chose one Freeside-owned fixture repository with fixed settings over a
disposable repository per project. The per-project rehearsal mixed two
questions:

- **Is this project runnable:** its settings, models, images, trust
  profile, and publication authority. Every per-project check the
  rehearsal ran was against the disposable repository's own trust
  profile, project image, recipe, review digest, and agent-tree commit, so
  none of it proved the real project's. Those checks belong to preflight:
  the readiness walk (#2222) and the per-role live smoke (#2208) run
  against the real project's settings and need no repository of their own.
- **Does this build's workflow trip:** launch, inputs, publication,
  completion, and alerts, end to end. That needs a repository, but one
  stable fixture for all of Freeside, not a ghost per project. A stable
  fixture also makes a pass on build N comparable with the pass on build
  N-1.

Rejected: keeping a disposable repository per project. Each project
needs its own repository, issue, and derived settings, and the pass
still proves nothing about the real project.

## Decisions

- **Live results stay beside the manifest.** The composition manifest is
  deterministic, content-digested, and bound by `submit
  --require-composition`. A live model call is neither deterministic nor
  free, so #2208's per-role smoke and #2222's live checks record their
  result as evidence beside the manifest, never as a manifest input.
  Composition preflight stays static, and the deputy's start calls no
  model.
- **The fixture pass uses the cheapest models that complete the
  workflow.** This revises the 2026-10-22 note, which kept each role's
  real model at `low`. Its reason, that a stand-in proves nothing about
  the model the real run picks, now lives in #2208, which calls each
  role's real model at its real effort against the real project. The
  fixture pass proves the workflow, not the models. The 2026-10-22 note's
  second decision, that the rehearsal submits the real run's task lines,
  goes with it: the fixture's fixed agent tree can't carry the real tree's
  agent names. `submit` checks only a line's shape, so until the
  readiness walk (#2222) checks the real lines before spend, a line the
  real tree can't honor is first refused at the real run's admission.
- **A same-build fixture pass stays a step of every exit run,** right
  before the real run. It is now cheap, with nothing to prepare per
  project, and the same-build rule is what makes the pass a claim about the binary. The
  mid-wave rehearsal unit runs the same pass on the midpoint build.
- **The fixture is `freeasinbird/freeside-review-challenge`,** the
  repository #1275 used. It is private, which #748 (PR #2240) allows: the
  daemon reads a bare-URL task's private source issue with a read-only
  installation token. Its canonical issue,
  freeasinbird/freeside-review-challenge#2, is sized for a clean review,
  because a review finding or a closure gate opens a card only a person
  can answer, which stops the pass.

## The Reset

Chose to reset the fixture before every pass over letting it accumulate
merged work: `main` is force-pushed back to the `fixture-baseline` tag, the
canonical issue is reopened, and the last pass's merged branch is deleted.
So `repository.base_sha`, the onboarding commit, and the task are the same
on every pass, which is what makes two passes comparable. The repository
is private on a free plan, which allows no branch protection, so nothing
blocks the force-push; if it ever gains protection, the reset needs a
bypass. The pass merges its own pull request, so the fixture's `AGENTS.md`
says the pass merges and then resets, in place of its old rule against
merging.

The canonical issue asks for one small, repeatable change: `canReserve`
returns `false` for a `count` below one, with a regression test and the
README's contract line. At the baseline, `canReserve(1, 3, 0)` returns
`true`.

## The Models

The writer and judgment roles run `claude-haiku-5-5` at `low`. Review runs
`gpt-6-luna` at `low`: in the bundled model catalog of the pinned Codex
CLI 0.162.1 (`codex debug models --bundled` in the review image), it is
the current listed model described as the affordable one for easier tasks.
Neither choice was proven served on the pinned images and accounts when
this note was written; `freesided probe-lineup` (#2208) checks it on the
fixture root before each pass. A role that is refused, or that fails to
complete the canonical issue, moves up one tier, and the walkthrough's
table moves with it.

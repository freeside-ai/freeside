## Why the Pin Moved

The second #2396 rehearsal pass refused its writer line `claude-haiku-5-5`
at `low` (`agent_resolution`): the enrollment's discovered catalog didn't
serve it. The catalog was right. On the daemon's own discovery call
(`initialize` under `--safe-mode`), 2.1.282 resolves `haiku` to
`claude-haiku-4-5-20251001` with no efforts and `sonnet` to
`claude-sonnet-5`; 2.1.319 resolves them to `claude-haiku-5-5` and
`claude-sonnet-5-5`, every model with low through max. 2.1.282 also logs
`unrecognized_model` for `claude-haiku-5-5`.

## Decisions

**Pin 2.1.319 over the npm `stable` tag's 2.1.311.** Both serve the same
five models with the same efforts. 2.1.319 is the build the issue measured
and every check below ran on; 2.1.311 had soaked longer under Anthropic's
stable channel. The owner may prefer stable; moving to it repeats this
re-proof on 2.1.311.

**Leave `ClaudeCallHarnessBuild` at 2.1.267 and the judgment host binary
alone.** The call adapter names its audited host build, not an image pin
(#1967), and the rehearsal's Haiku 5.5 judgment line already passed its
lineup probe on the 2.1.282 host binary.

**Move the prompt-stdin probe's version assertion to the pin.** It still
asserted 2.1.220 because #2195 couldn't run it without a held rig. Its
skip message says it needs the pinned build, so it follows the pin.

**Keep the 2.1.282 usage fixtures and add a 2.1.319 one.** The parser has
to read both while deployments move, and the new capture pins 2.1.319's
event shape.

## Re-Proven on Claude Code 2.1.319

Offline, on the built image with `--network none`, beside the 2.1.282 image
as a control:

- `claude --version` reports 2.1.319 (the build script asserts it), and
  `scripts/check-agent-image.sh` passes.
- Root refuses `--dangerously-skip-permissions` without `IS_SANDBOX=1`.
- A launch that can't reach the provider exits nonzero.
- `--safe-mode` suppresses planted project and user `SessionStart` and
  `UserPromptSubmit` hooks under the writer argv as uid 1001; without it,
  all four fire.
- The discovery answer lists `claude-haiku-5-5` with `low`.

With the production usage driver on the host package, against a loopback
mock API that sends both windows' headers, a synthetic OAuth token, and the
writer's scope override (`CLAUDE_CODE_OAUTH_SCOPES`), run on both builds:

- `get_usage` answers `rate_limits` with `five_hour` and `seven_day`, so
  `claudeUsageWindowLengths` holds. The event adds a `status` to each
  unified window, which the parser ignores. On this mock neither build's
  event carries a top-level `resetsAt` (the mock sends no overall reset
  header), so the missing field in the 2.1.319 fixture is the mock's, not
  the build's. Only the `allowed` status token was observed; the other
  tokens the collector reads weren't exercised.
- A refused turn (400) exits 1 and answers null shares, as on 2.1.282.
- Without the scope override, both builds answer
  `rate_limits_available: false`; the override still matters.
- After a turn under the token in `CLAUDE_CODE_OAUTH_TOKEN`, neither build
  leaves the token or a `.credentials.json` anywhere in its config dir.
  2.1.319 adds one write there, `plugins/store/<plugin>.json`. The writer's
  config dir is ward's writable config-root volume
  (`ward.ClaudeConfigRootTarget`), not the read-only credential mount, and
  the production-line probes below exit 0 with it.

Live, under a held rig with no provider credential:
`TestPinnedClaudeUsageDriverLive`, `TestPinnedClaudePromptStdinLive`, and
`TestPinnedClaudeInputReadLive` pass. In ward's live suite, the conformance
suite, its same-VM refutation, handoff lifecycle, workspace seeding,
worker git identity (both vendors), concurrent read-held writers, and the
declared size and memory kill all pass on the new image.

## Tool Surface Delta

The `system` init event under the writer argv, compared with 2.1.282's.
The shadow reviewer's argv (`internal/ward/claude_review.go`, with
`--allowedTools Read Grep Glob`) shows the same tool delta, also with no
MCP server:

- **Tools:** adds `Monitor` and drops `WebFetch`. `WebSearch` (a
  server-side tool) is on both builds.
- **Built-in plugins:** `agents-md` becomes `cc-plugin-agents-md`, and
  `cc-plugin-sec-default`, `cc-plugin-privacy`, and
  `cc-plugin-plugin-authoring` join it. `mcp_servers` stays empty.
- **Skills and commands:** adds the `plugin-authoring` skill and the
  `insights` command.

None adds an egress route or a credential path. `Monitor` runs a
command and streams its output, inside the same VM and under the same drop
as `Bash`, and
the plugins are in-binary prompt content with no MCP server. Egress is still
the ward proxy's allowlist, which the conformance suite checks.

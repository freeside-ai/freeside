# Go 1.27.3 and golangci-lint 2.15.0 in Go Images and CI

The agent chose, for #2799, to suppress gosec's G703 at each of the three
sites it newly flags instead of excluding the rule, and to land the CI lint
bump and all of its fixes in one commit. Moving the Go image to Go 1.27.3 and
golangci-lint 2.15.0 changes the preparation digest, so every recorded
project image is rebuilt once after the upgrade.

## G703 Is Suppressed Per Site, Not Excluded

Under golangci-lint 2.15.0, gosec's G703 (path traversal found by taint
analysis) newly flags, on some runs, three calls in
`readCodexReviewInputWithMetadata` (`daemon/internal/ward/codex_review.go`):
`os.Lstat(root)`, `os.Lstat(file)`, and `os.OpenFile(resolvedFile, …)`.

Chose a `//nolint:gosec` directive with a G703 reason at each site (its
final form is under the next heading) over a G703 exclude in
`daemon/.golangci.yml`. The function is the guard that makes these reads
safe, so the reasons belong at its calls. A global exclude would also hide
the rule from every later file read that has no such guard.

The refute-first pass tried to show each site unbounded. Each claim was
disproved by reading the guard and the tests that pin it:

- **`os.Lstat(root)` reads attacker-chosen metadata.** Disproved: Lstat
  returns only metadata, and the function refuses unless the root is a
  directory owned by the effective user with no group or other permission
  bits.
- **`os.Lstat(file)` runs before the containment check.** Disproved: it reads
  only metadata, and its result is used to require a regular file and,
  after the open, as the identity the opened file must match
  (`os.SameFile`). Nothing is read from the file before containment holds.
- **`os.OpenFile(resolvedFile)` can open outside the root.** Disproved:
  `resolvedFile` is `filepath.EvalSymlinks(file)`, `filepath.Rel` from the
  resolved root must not climb out, `cliSafe` must pass, and the open uses
  `O_NOFOLLOW`. Swapping a component after resolution needs access below
  the private root, which no other user can even traverse, and the
  post-open checks still require the same inode, a regular file owned by
  that user, no group or other bits, and one link.

`TestCodexReviewSingleFileBindsStayUnderTrustedRoot` (`codex_review_test.go`)
pins these refusals: an input outside the root, a symlinked, hard-linked, or
shared input, and a shared root.

The directives change no compiled code, so no behavior comparison was run.

### Gosec Reports G703 Here on Only Some Runs

The directives name `nolintlint` as well as `gosec`
(`//nolint:gosec,nolintlint // G703: <reason>`), because gosec 2.29.0's
G703 result at these sites changes from run to run. On the landing
batch's rebased head, CI's lint failed once with all three directives
unused and passed on a rerun of the same commit, with the same restored
caches and a cold lint cache both times. That one pair is the only
observed flip; no local run reproduced it.

The cause is upstream. `cha.CallGraph` in `x/tools` builds each function's
incoming edges by ranging over a map, so caller order varies per run.
Gosec's taint walk shares one visited set across those callers, stops at
depth 50 and after checking 32 caller edges per function, and caches only
positive results, so whether `root` and `file` read as tainted depends on
which caller it visits first.

Chose the per-site `nolintlint` exemption over the alternatives:

- **`nolintlint.allow-unused: true`** would stop the unused check for every
  directive in the daemon.
- **A G703 exclude for `codex_review.go`** would hide the rule from every
  later file read in that Tier A file.
- **Routing the paths through a gosec sanitizer** (`filepath.Base` or
  `filepath.Rel`) would change compiled code in the guard to quiet a linter.
- **Accepting the flake** would fail lint at random on every PR once this
  merges.

The exemption also stops nolintlint from checking these three directives
for a missing explanation, which costs nothing while the explanations are
there. Drop `nolintlint` from them once a gosec release reports G703
deterministically. Any other site G703 newly flags is open to the same
flake, in the other direction: an unsuppressed site can fail lint on some
runs.

## The Lint Bump Is One Commit

golangci-lint 2.15.0 reports 14 findings on the daemon at `7a79d9ec1`, and
v2.12.2 rejects every fix:

- The gofumpt reformat in seven files is "not properly formatted" to the
  v2.12.2 gofumpt, which is built with Go 1.26.
- The three errcheck and three G703 directives are unused to v2.12.2, so its
  nolintlint rejects them. `_ = <-ch` is not an alternative for the errcheck
  sites: staticcheck's S1005 rejects it under both versions.
- Removing the `paralleltest` directive on the `t.Chdir` test, which v2.15.0
  reports as unused, makes v2.12.2's paralleltest flag the test.

So the CI pin and the fixes land together, and no smaller commit is green.
The reformat can't be its own blame-ignored commit for the same reason, and
the commit isn't listed in `.git-blame-ignore-revs` because it carries
non-mechanical lines. Local lint must use the release binary: a
golangci-lint built with Go 1.26, such as `go run …@v2.15.0` under Go 1.26
or Homebrew's 2.12.2, formats differently from the release, which is built
with go1.27.0.

## Upgrade Cost: Every Recorded Image Rebuilds

`PreparationDigest()` hashes the toolchain pins, and one digest covers npm
and Go images. A daemon with the new pins treats every image an earlier
daemon built as not current, even at its own build commit. Image selection
skips it, so attempts hold under `image_upkeep_pending` (`rebuild`) until
the image-upkeep start pass rebuilds the image at the tip, with the same
proofs and one-hour bound as a publication rebuild, and advances the
pointer. No re-approval is needed: the onboarding approval binds the recipe
digest and image request, not the preparation digest.

Freeside isn't onboarded against its own repository yet (#2338), so this
costs only other onboarded repositories one rebuild each.

A module that names `toolchain go1.26.10` is no longer served, because the
image refuses any toolchain other than the baked one. Freeside's
`daemon/go.mod` and `scripts/trackercollect/go.mod` name none.

# Production Claude Driver: Topology Gate, Credential Posture, and Export Binding

Work unit: #237 implementation slice (driver, `freesided submit`, production
`ExecutionExport` writer, real-run harness). This note carries the mandatory
trust-boundary record: the Early Claude Instruction-Topology Gate evidence and
adjudication, the credential-delivery posture decision, and the export/result
commit-ordering decision #318 will bind against.

## Early Claude Instruction-Topology Gate

Contract under test (issue #237; #375/#376 ward topology): the pinned
authenticated Claude CLI (2.1.220) must load the exact admitted host-vendor
instruction sentinel from the read-only native user-instruction mount
(`/root/.claude` containing exactly `CLAUDE.md`), complete real inference, and
perform required runtime-state behavior across startup, recovery, resume, and
child-process launch, with at most one writable mount (the leased auth-store
volume). A shell-only mount probe is not acceptance evidence.

Stop-the-lane criteria: every sentinel-passing variant needs writes under
`/root/.claude`; or a second writable mount; or relocated state breaks sentinel
loading; or only an env-token path authenticates and that violates the §5.4
mount posture. On stop: file the spine `kind:contract` topology issue, halt the
unit.

### Gate Verdict: #383 Replaced And #378 Proved The Topology

**The first gate failed, then #383 supplied and proved the replacement.** The
production driver now carries an empty `AgentSpec.Env`, mounts the identity
token volume read-only, and has the launcher read its single `token` file into
`CLAUDE_CODE_OAUTH_TOKEN` only for the Claude process. Fixed launch variables
move into the launcher, which uses `--safe-mode`, a daemon-chosen session ID,
and the explicit instruction-bundle flag.

The writer outcome leg now uses the journalled unpredictable run nonce. The
launcher's final act writes `<nonce> <status>`; ward reads it through a
credential-free read-only observer after writer absence. Only matching zero
plus proxy-health-throughout earns `WriterComplete`. Matching nonzero is
durable before cleanup and closes failed; recovery classifies the crash window
between marker write and amendment, then the driver converges the canonical
failed `ExecutionOutcome`. Missing, malformed, mismatched, or zero without the
live proof closes loss and never reaches the exporter.

**Implementation realization:** ward now creates and independently proves the
fresh config root, invocation continuity, and launch scratch as separate
runtime objects. Their fingerprints, exact nested targets, mount modes, and
manifest digests are durable before writer creation and re-inspected before
start. The explicit bundle is composed only from the gate-owned exact-base
snapshot plus the admitted host role, independently observed, and journalled
by composition version, complete source-manifest digest, and result digest.

**Final verdict:** pass. The authenticated rerun above uses the production
credential target, config and instruction targets, mount modes, safe-mode
argv, exact session flags, and pinned image. Per #383's merged decision note,
Phase 1A has no daemon-mediated Claude follow-on; adding an unused production
resume launch kind is explicitly deferred until a real follow-on requires the
newly reviewed lease/fence boundary. The gate proves that the implemented
state and instruction topology retains exact forked resume without inventing
that absent call site. #237 stays open for the post-#318 acceptance slice.

## Credential Delivery Posture

**Decision (revised by #383): the identity-persistent volume contains only a
0400 setup-token file and is mounted read-only.** `CLAUDE_CONFIG_DIR` names a
fresh per-launch clean state root, never that token volume. The launcher reads
the token into the Claude process environment at exec; the value appears in
neither the configured container environment nor launcher argv text.

Rejected alternative: passing `CLAUDE_CODE_OAUTH_TOKEN` in `AgentSpec.Env`.
It is the shortest path and the probes used it, but ward records the writer's
environment in the inspect report the conformance check compares, so the
token would land in an audit artifact and in the container's own process
environment, readable by anything the agent runs. §5.4's containment argument
is that the credential is a mounted store, not an ambient value.

The accepted residual is explicit: the token is ambient in the writer process
tree and readable from its mount at agent privilege. Provider-only egress and
the export scanner are the backstops; #384 adds the Anthropic-token scanner
rule before this exposure is accepted for real exports.

## Evidence Before Export Before Result

The driver persists the released manifests, evidence blobs, and agent claims
before recording the `ExecutionExport`, then commits the Collect-visible
`StageResult`. This preserves both directions of the audit contract: every
observable completed head already has its export binding, and every export
binding already resolves to its evidence. A crash may leave unreferenced
content-addressed bytes, which an identical replay converges on; it can never
leave a durable row that asserts missing evidence. Rejected: recording the
export first, because a later evidence failure made the audit row false.

## Other Decisions This Slice Made

- **Production lane ownership is the dispatch intent's outbox row**, not a
  new attention item. A Run carries no workflow discriminator, so each lane
  needs a concrete marker; the outbox row already exists, is written in the
  same transaction as the run, and cannot be acquired retroactively by a
  foreign run. Rejected: a `run_proposal` marker item, which would surface an
  attention item for work the operator already approved at submit time.
- **Terminal outcomes are recorded, not raised as loop failures.** The
  walking skeleton fails the reconcile loop on a failed or lost invocation,
  which predates any failure-item vocabulary. Unattended operation cannot
  wedge the engine on one bad run, so the production lane records the
  terminal class in a durable inbox row and raises a deterministic
  `execution_failure` item.
- **Base is operator-pinned per daemon (`-base-sha`), not resolved per run.**
  Resolving a branch tip at admission would need a publish-lane transport
  capability that does not exist, and pinning the base on the Run would be a
  shared domain change. Only the workspace is derived per attempt, which it
  must be, since each handoff owns its volume. Recorded as a deliberate
  limitation: several sequential work items share one base until a run-pinned
  base contract exists.
- **Conformance is not run at daemon startup.** Unattended admission requires
  a durable, generation-current conformance record (#327, #320) that the
  store re-gates on every admission; a daemon that minted its own proof at
  startup would be attesting to itself. It stays an operator precondition, so
  a daemon started without one admits nothing.
- **The credential scan is a pattern scan, and says so.** ward requires a
  check-7 scanner and nothing implemented one. Its stated scope is material
  copied into the workspace, not material the agent encoded; its error names
  the file and pattern class but never the match, so a leak report is not a
  second copy of the credential.

## Refute-First Verification Pass

Two fresh-context lenses were run against the branch diff before push, each
prompted to disprove the unit's containment and durability claims (this unit
is a credential-leak surface and a returned-object trust boundary). Recorded
so confirmed findings are not re-raised and rejected ones are not re-argued.

**Confirmed and fixed:**

- **The daemon could not start in claude mode**: `ward.Config` was built
  without `ExporterCommand`, which the ward requires. Every claim about the
  production composition was therefore untested end to end. Now supplied from
  `export.HelperCommand()`, so the daemon and the image cannot drift on how
  the export is produced.
- **The credential scan was a silent false negative past 8 MiB**: it
  truncated each file and reported the remainder clean. The export's largest
  member is the agent's own transcript, which is both the most likely to
  exceed a cap and the most likely to echo auth material. Now streamed in
  overlapping chunks, whole file, bounded working set.
- **Export convergence could never converge**: `ExecutionExport` carries the
  evidence digest as a pointer, and the constructor and the store's decode
  each allocate their own, so `==` compared addresses. Every
  evidence-carrying replay would have been reported as a conflict, turning
  the exact crash window the convergence exists to close into a durable
  failure. Now compared by value, with a regression test.
- **The intent file was a decode boundary with no re-gate**: a tampered or
  corrupted record could retarget a recovered run's image, base, identity, or
  workspace. It now re-runs the containment gate on read, authenticates the
  full start against the durable admission, requires the exact derived seed
  path, and re-hashes the stored input and vendor-instruction bytes before
  reconstructing the prompt.
- **`-allowed-paths` defaulted to `**`**: declared-path scope is a §5.6/§5.8
  containment control, so unattended mode now refuses to start without
  explicit paths.
- **The importer was not bound to the admitted trust profile**: the production
  composition supplied only the operator allowlist, so repository-specific
  protected paths, commit-plan mode, and message rules were absent. Import now
  loads the exact profile digest from the authenticated admission and widens
  policy through `WithProtectedPaths`.
- **Submitted policy was opaque input**: arbitrary bytes were accepted,
  materialized, and then omitted from the agent prompt. Submit now strictly
  decodes resolved policy keys with per-key provenance, persists the
  `ResolvedPolicy` in the run transaction, stores the canonical keyed bytes,
  and includes those verified bytes in the rendered prompt.
- **Importer findings were ignored**: a non-empty finding set alongside a
  commit SHA could be surfaced as a completed candidate. Any finding now
  fails the stage before an export row is recorded.
- **Released export state was trusted twice**: both a fresh gate return and a
  decoded recovery record could supply an arbitrary cleanup path or fields
  inconsistent with the files on disk. The driver now requires the
  run-derived temporary-directory shape, a plain directory, the admitted
  observed base, and canonical manifest/evidence bytes before import or
  deletion.
- **Oversized admitted submissions wedged dispatch**: prompt rendering
  returned a start error after the outbox had dispatched, so every daemon
  restart retried and exited on the same work item. Unsupported rendered
  input now commits an authenticated failed result that the production lane
  surfaces as `execution_failure`.
- **Recovered exports repeated an already-closed ward recovery**: the first
  post-restart `RecoveryExported` return resumed import while the intent still
  said `running`, so another crash asked ward to recover its now-closed
  journal. Recovery now persists the same `exported` phase as a fresh handoff
  before import resumes.
- **Committed results were private-state assertions**: a valid-shaped edit to
  the intent could replace a completed head, evidence list, or status. A
  completed result is now accepted only when its phase-specific export
  payload hashes to the durable `ExecutionExport`, and non-completed/lost
  states are rejected when that row exists.
- **Export lookup errors were collapsed into absence**: transient store or
  admission re-gate failures permanently marked the run lost. The port now
  distinguishes confirmed absence from failure; failure leaves the exported
  intent retryable and fails startup closed.
- **Directory-free recovery dropped evidence identities**: when the export
  directory was gone, the fallback reconstructed only the head. It now
  authenticates the decoded evidence manifest against the durable row and
  restores the same ordered artifact digests as normal completion.
- **Production acceptance inherited the legacy missing-admission exception**:
  production dispatch requires an admission, but the shared completion gate
  treats an absent row as a pre-contract attempt and therefore accepted a
  completed production result after its audit authority disappeared.
  Production completion now requires that the row exists and passes the
  current reconstruction policy; the legacy exception remains scoped to the
  older conversation lane.
- **Fresh success overwrote its exported phase with a stale caller copy**:
  the pipeline advanced a local value inside `handoffAndImport`, then
  committed from the original seeding-phase value. The resulting completed
  intent carried no released export and failed its own reconstruction gate.
  Terminal commits now accept only the invocation identity and reconstruct
  the current durable phase before changing it. The independent class sweep
  applied the same rule to both recovery-loss paths, so neither terminal
  transition can erase a newer phase.
- **The evidence credential scanner drifted behind the importer scanner**:
  fine-grained GitHub PATs could be retained in durable evidence even though
  the later importer scan recognized the same shape only in candidate
  content. The whole-export scanner now covers every high-signal class the
  importer already recognizes (fine-grained GitHub, Slack, numeric-labelled
  PEM, and GCP service-account identifiers), in addition to its
  Claude-specific token pattern.
- **A persisted conformance pass did not survive daemon restart in the live
  declaration**: the store admitted against the durable proof, but a newly
  composed ward backend advertised only its three base capabilities, so the
  unattended floor refused every dispatch forever. Composition now restores
  only the latest persisted passed generation before dispatch; ward refuses
  unpersisted or failed records and refuses a restore after any live recheck
  has begun, so an old success cannot resurrect cleared capabilities.
- **The first restore fix was class-bound but not configuration-bound**: a
  changed exporter image, container command, or provider allowlist could
  inherit suite-earned capabilities from the previous active values. Durable
  conformance now carries a canonical configuration digest produced by ward;
  restore requires exact equality. Migration preserves pre-binding rows under
  a reserved unbound digest that remains readable audit history but cannot be
  newly written, restored, or used for unattended admission.
- **A well-shaped terminal inbox row could suppress the real driver
  outcome**: strict decoding authenticated only the row's identities and
  terminal status. The at-most-once guard now re-collects the driver's
  durable terminal outcome, requires exact status, head, artifact, and
  summary equality, and re-runs current admission for completed results.
- **The released-directory shape was not ownership**: a decoded driver
  intent could name any same-run, same-prefix temporary directory before an
  `ExecutionExport` existed, and the driver would read and later remove it.
  Ward now authenticates the caller-supplied directory by exact equality
  against the closed-completed handoff journal. The journal value is used
  only as a comparison reference, never as a path source for I/O or cleanup.
- **Restart enumeration did not bind a record to its filename**: a stale
  intent copied under another `.json` name could pass the payload regates and
  later overwrite the canonical committed record when recovery advanced it,
  rewinding an invocation. Enumeration now accepts only a plain regular file
  whose name is the canonical hash-derived name for its decoded invocation;
  both enumeration and direct reads also reject duplicate keys, unknown
  fields, and trailing JSON values.
- **A ward recovery error was mistaken for a terminal stage failure**:
  `phaseRunning` means the credential-bearing writer may still exist until
  ward returns an explicit exported or loss outcome. Committing a failed
  result on a transient journal/runtime error skipped all future recovery and
  teardown. The entire pre-outcome path now stays retryable and preserves the
  running intent.
- **Conformance identity omitted the writer image**: `Suite.Full` and
  `PreJob` execute the configured agent image, but the durable configuration
  digest named only the runtime and exporter surfaces. A changed
  `-agent-image` could therefore restore proof earned by different bytes.
  Ward's configuration identity now includes the pinned agent image, suite
  construction rejects a mismatched fixture, and production `PreJob` uses
  that same bound image.
- **Production dispatch skipped the required lightweight pre-job probe**:
  the store re-gated the last full proof, but no runtime liveness check ran
  before a real start. The Claude driver now invokes ward's bound-image
  `PreJob` after duplicate arbitration and before materialization or durable
  intent creation; a refusal starts nothing.
- **Equivalent match-all allowlists bypassed the literal `**` refusal**:
  patterns such as `**/*` and `*/**` still span every repository path.
  Production configuration now requires each declared pattern to begin with
  a literal top-level repository path, and adversarial spellings are covered
  as one class.
- **Non-export terminal state had no independent durable authority**: a
  valid-shaped edit to the private intent could invent a failed, canceled, or
  lost outcome and permanently suppress ward recovery. A write-once
  `execution_outcomes` record now authenticates exactly those three
  non-export classes against the admission; completed work remains
  authenticated only by `ExecutionExport`, so the two authorities cannot
  overlap.
- **Conformance identity named the runtime path, not its bytes**: replacing
  the Apple `container` executable in place could restore isolation proof
  earned by the previous binary. Ward now resolves and hashes the executable
  into the configuration digest at construction, and `PreJob` recomputes the
  identity before every production dispatch so a post-restore replacement
  refuses work.
- **Conformance identity omitted the daemon implementation that earned it**:
  an upgraded freesided/ward binary could restore suite capabilities proved
  by older network, export, lease, or scanner code whenever every external
  setting stayed equal. The v3 configuration identity now includes the exact
  daemon executable bytes as well as the runtime executable, so any rebuild
  requires a fresh full pass before unattended admission resumes.
- **A live handoff error was also mistaken for proof of teardown**: even
  outside restart recovery, ward can return an operational error joined with
  a failed reap while the credential-bearing writer still exists. The driver
  no longer records a failed/canceled terminal from `phaseRunning`; it leaves
  that phase for ward recovery to produce an explicit export or loss outcome.
- **Preserving live handoff state did not schedule recovery in the current
  process**: the completed local session was removed, but ward recovery ran
  only at daemon startup. The next engine pass saw a gone invocation with no
  result and stopped the daemon. Inspection now adopts an orphan through the
  same recovery path, holds retryable ward errors as running, and retries on
  later passes; recovery arbitration prevents concurrent adopters.
- **A successful handoff was still not durable at the journal-closing
  boundary**: authentication, validation, and the exported-phase write all ran
  after ward closed the journal while the intent still said `running`; the
  same gap recurred when ward recovery returned an export. The complete return
  from either path is now persisted immediately as untrusted replay data,
  re-authenticated before any I/O, and retained in process for an exact write
  retry if that first persistence attempt fails.
- **Admissions named a backend class but not its proven configuration**: two
  live daemons could race configuration A against a newer durable proof for B,
  combining A's in-memory capabilities with B's authority. Unattended
  admissions now content-bind the backend configuration, and the admitting
  transaction requires exact equality with the latest conformance record.
  Start and recovery re-run the same check because an already-recorded attempt
  otherwise bypasses fresh admission after a restart under B.
- **A transient pre-job failure stopped the reconcile loop**: the lightweight
  probe correctly refused process start, but its error escaped as a daemon
  failure. The driver now marks this operating-state refusal explicitly and
  the engine leaves the outbox intent pending for a later healthy pass.
- **Transient input I/O stopped every production submission**: an admitted
  blob-store open, read, close, or cancellation failure occurred before any
  driver intent existed but escaped `Start` as a fatal reconcile error. The
  production input adapter and materializer now mark only operational I/O as
  retryable, so the outbox item remains pending and unrelated engine work can
  continue. Missing blobs, invalid addresses, digest mismatches, and size
  violations retain their permanent integrity classes and still fail loud.
- **Terminal intent persistence errors were discarded**: a pipeline could
  finish after its durable outcome/export landed, fail to save the collectable
  terminal phase, and then delete its only in-process retry state. The session
  now retains the pending result, surfaces repeated write failures, and retries
  the exact terminal commit from `Inspect` or `Collect`.
- **Invalid UTF-8 could split prompt identity from persisted inputs**:
  converting arbitrary admitted bytes to a Go string let JSON persistence
  replace invalid sequences while the digest-bound input bytes remained
  unchanged. Prompt rendering now refuses non-UTF-8 prompt packages,
  specifications, and policies before any intent is written.
- **The first admission binding made pre-v3 audit history unreadable**:
  historical unattended admissions omit the configuration field and retain
  their v1/v2 content identity. Reconstruction now permits that omission while
  the constructor and every execution/recovery/acceptance gate still refuse to
  use or create an unbound unattended admission.
- **Expected conformance drift stopped the daemon instead of holding work**:
  a newer proof for configuration B makes daemon A's admission fail closed,
  but that operating-state refusal escaped the production hold classifier.
  Every backend-conformance refusal now leaves the outbox pending; unrelated
  correctness errors still stop reconciliation.
- **Daemon shutdown did not own live Claude sessions**: the driver detached
  each pipeline from its short reconcile context, but the daemon neither
  canceled nor awaited those sessions before closing the store. Pipelines now
  inherit a daemon-lifetime context, shutdown closes the driver to new starts,
  and every live session is canceled and awaited through ward teardown before
  store close.
- **The legacy invocation loop missed the unattended refusal classifier**:
  the production loop held capability, pre-job, and conformance refusals, but
  a conversation-bound invocation using the same Claude composition still
  stopped the daemon. Both loops now use the same typed hold predicate, and a
  healthy later pass resumes the still-pending legacy intent.
- **Retryable orphan recovery still aborted daemon startup**: the driver
  preserved a running/exported intent on temporary journal, filesystem, or
  store failure, but composition returned that explicit retry class as a
  fatal startup error. Startup now holds only that class so the engine's later
  `Inspect` pass retries it; permanent reconstruction failures still abort.
- **The live harness overstated its finish line**: it proves the production
  path through a durable `ExecutionExport`, not #318's clean verification or
  publication binding. Its name, comments, and positive success signal now
  state that pre-publication boundary explicitly.
- **Terminal-summary truncation could corrupt its durable identity**: byte
  slicing could split a multibyte rune and the appended ellipsis could exceed
  the claimed cap. The extracted SQLite column then retained invalid bytes
  while JSON encoding replaced them, so reconstruction rejected the row.
  Summaries are now normalized, truncated at a rune boundary, and bounded
  including the suffix.
- **A closed successful journal still had a return-to-save crash window**:
  ward durably closed the completed record before returning its verified
  export, but a daemon crash before the driver persisted `phaseExported`
  restarted from `phaseRunning`; recovery then refused the already-closed
  record forever. Closed recovery is now idempotent. It authenticates the
  original spec and journal state, accepts only ward's exact random temporary
  path shape and a real directory, and re-runs manifest, evidence, stray-file,
  digest, and credential scanning before replaying the export. A closed loss
  replays its durable rerun-safe signal without touching runtime objects.
  Tampered paths or post-close content refuse without deleting the evidence.
- **Post-export operational failures destroyed replayable work**: after the
  durable `exported` phase, fetch, import-process, artifact-store, ambiguous
  export-record, or shutdown errors all ran through unconditional directory
  cleanup and then became failed/canceled outcomes. The driver now deletes a
  released directory only after success or a conclusive candidate-controlled
  trust-boundary rejection. Operational and unknown failures retain the exact
  export and phase under `ErrRecoveryRetryable`; validation also distinguishes
  I/O failures from authenticated field mismatches. The definitive importer
  allow-set is intentionally narrow because sentinels such as
  `ErrMissingBlob` also wrap operating-system open failures.
- **A conflicting durable export had no valid state transition**: treating a
  confirmed `ExecutionExport` mismatch as retryable hid corruption forever,
  while treating it as an ordinary stage failure would record a contradictory
  non-completed authority beside the existing export. Both the live write
  convergence path and directory-free recovery now preserve the released
  evidence and `exported` intent but return a distinct non-retryable error,
  stopping recovery for operator repair without minting an outcome row.
- **The store did not enforce disjoint terminal authorities**: migration 0021
  described `execution_exports` and `execution_outcomes` as mutually exclusive,
  but either writer could insert beside the other. Both store APIs now reject
  the opposite authority inside their write transaction, and reciprocal
  SQLite triggers preserve the invariant for raw writes and future callers.
  The driver also recognizes an outcome write refused by an existing export
  as the same non-retryable authority conflict, rather than retaining a
  terminal write that can never succeed. Recovery now consults that authority
  before a leftover released directory: a valid export completes from the
  durable record even if the expendable directory was later changed or lost.
- **Current conformance incorrectly gated terminal history**: completed and
  lost intents now re-authenticate their exact immutable admission plus export
  or outcome without re-applying the latest backend proof, active trust-profile
  revision, or backup posture. The same applies to an exported-phase crash
  window once its matching `ExecutionExport` exists; seeding, running, and
  unrecorded exported intents still use the current policy-gated admission
  read and require configuration-bound conformance before they can start,
  recover, or import.
- **The default submit identity omitted fixed bindings**: the default run ID
  now derives from project, specification digest, and canonical resolved-policy
  digest. Exact resubmissions converge, while shared specification bytes in a
  different project or under different policy create distinct work items.
- **The prompt cap exceeded Linux's single-argument limit after quoting**:
  the writer still receives the prompt through the frozen `sh -c` topology,
  but the accepted prompt is now capped at 31 KiB. Even the worst-case
  apostrophe expansion plus fixed command text stays below 128 KiB; larger
  prompts remain a future ward prompt-mount contract rather than an `E2BIG`
  process-launch failure.
- **Deterministic prompt refusals bypassed terminal authentication**: the
  oversized/non-UTF-8 reconstruction branch now requires the same immutable
  `ExecutionOutcome` authority as every other non-export terminal result.
- **Mutable policy drift stranded both sides of the terminal boundary**:
  failed, canceled, and lost outcome writes re-applied current admission
  policy, so a trust-profile or backup change could make terminal history
  impossible to persist. Completed results awaiting first acceptance treated
  the same expected drift as a fatal reconcile error, while recorded
  completions incorrectly re-gated it on every replay. Non-export outcomes
  now bind to the immutable admission record; first completion acceptance
  classifies the complete mutable-policy refusal set as a hold; recorded
  terminal replay authenticates immutable admission and driver outcome
  authority without consulting current policy. The first-acceptance gate is
  repeated inside the terminal write transaction, closing the interleaving
  window between the pre-write gate and acceptance. Corruption and immutable
  binding errors remain fatal.
- **Outcome-written intent-not-written still crossed the mutable gate first**:
  a failed, canceled, or lost authority could commit before the private phase
  update, leaving a stale preterminal intent that current trust or backup
  policy then refused forever. Reconstruction now authenticates the immutable
  admission, restores a matching write-once outcome, and only then selects the
  terminal versus current-policy gate. Restart persists the recovered terminal
  phase; malformed, foreign-admission, or conflicting records remain fatal.
- **Two startup windows still stranded credential-bearing work**: a handoff
  refused before its atomic journal/lease open remained `running`, so every
  later pass asked ward to recover a record that could never exist. The
  driver now queries authenticated journal presence: confirmed absence
  returns the intent to `seeding` for a safe rerun, while an opened record
  remains recovery-only. Separately, orphan reconciliation could resume a
  session before backup maintenance failed startup, but driver cleanup was
  installed only on the successfully constructed daemon. Startup now
  registers awaited driver close immediately after composition and runs it
  before closing the store on every later failure.
- **Artifact identity omitted immutable claim provenance**: identical evidence
  bytes from one invocation could carry different head or sensitivity
  provenance under different labels, but the old ID used only invocation and
  digest, so the second immutable Artifact row conflicted. Agent artifact IDs
  now cover the complete provenance tuple plus content digest.
- **Default run identity retained only 48 hash bits**: project, specification,
  and policy were all bound, but an intentionally generated 12-hex-prefix
  collision still made distinct submissions contend for one immutable run.
  The derived ID now retains the full SHA-256.
- **Pre-handoff operational failures terminalized rerunnable work**: daemon
  shutdown or a transient exact-base fetch left no writer or ward journal but
  still recorded a failed/canceled outcome. The production seeder now marks
  cancellation, rate limiting, server failures, and ambiguous transport
  failures retryable while exact-base absence and explicit Git/API or durable
  credential refusals remain terminal. A definitive refusal outranks
  concurrent shutdown; recovery resumes the preserved `seeding` intent
  through the current policy gate.
- **Terminal attempts leaked both daemon-owned checkouts**: the seed and a
  crash-orphaned import checkout survived every terminal outcome. Cleanup now
  runs only after the terminal intent is durable, retries on terminal reads
  and restart without withholding the authenticated result, and deletes only
  run-derived names through the `os.Root` handle pinned when the driver claims
  `SeedRoot`. Refute-first fixtures proved preterminal and failed-persistence
  preservation, invalid-phase refusal, restart cleanup, child-symlink
  containment, and root-path replacement containment. Reopening the root by
  pathname was rejected because a rename-and-symlink race redirected deletion.
- **An invocation-local input hold starved later submissions**: operational
  input I/O correctly preserved the affected outbox row, but returned from the
  entire ordered dispatch pass. Input unavailability now continues to the next
  intent while backend conformance and other global gates still stop the pass.
  A two-submission regression holds the first invocation, starts the healthy
  second one, then proves a later pass resumes the held work.
- **Malformed base bindings became permanent retries**: composition accepted
  invalid repository, branch, and commit values into durable admission, then
  the seeder treated transport's local validation error as operational. The
  claude driver now applies the transport's exact repository and branch gates
  plus the full lowercase commit-SHA grammar before accepting configuration.
- **Submission artifact identities retained only 48 hash bits**: specification
  and policy artifacts, including their producer invocation IDs, could collide
  despite distinct content digests. Every submission-derived artifact and
  producer identity now retains the full SHA-256; a constructed shared-prefix
  regression proves the two artifacts remain distinct.
- **Mutable admission drift still stopped first dispatch**: the terminal
  acceptance path recognized the complete mutable-policy refusal set, but
  first dispatch recognized only its backend-conformance subset. Both dispatch
  lanes now hold the same complete set for a later admissible pass; corruption
  and immutable binding errors remain fatal.
- **Post-fetch auth-store lookup cancellation terminalized unstarted work**:
  the exact base was seeded, but rebuilding the handoff spec could fail its
  context-backed auth-store lookup before ward opened a journal or writer. That
  operational window now remains in `seeding` under the retryable recovery
  class. Static containment refusals still fail terminally, and the initial
  pre-durable handoff-spec check still refuses without committing an intent.
- **Stopped was incorrectly treated as writer success**: Apple container does
  not report exit status. The nonce marker and journal amendments above now
  refuse every nonzero process before export, including recovery across the
  pre-amendment crash window. The independent review then disproved the
  marker's original trust claim: a root-running tool could read the nonce
  from PID 1, write a forged zero marker, and kill the wrapper; a disposable
  container reproduced that exact false pass. The launcher now retains its
  root wrapper but drops Claude and every tool to UID/GID 1001 with no
  capabilities or privilege regain. A root-owned sticky workspace boundary
  keeps the evidence channel writable while a root-only control subdirectory
  protects the outcome marker; the untrusted child can neither replace that
  directory nor signal the wrapper.
- **Startup recovery treated mutable policy as fatal**: startup now uses the
  engine's same complete typed mutable-policy classifier, so stale checkpoint
  or conformance evidence holds the orphan until maintenance or policy repair;
  immutable corruption remains startup-fatal.
- **Mutable policy blocked terminalization and cancellation**: current-policy
  drift after admission could permanently suppress a pending terminal result
  and prevent the live credential-bearing writer from being canceled. Those
  transitions now reconstruct against immutable admission while starts and
  recovery retain the current-policy gate; adversarial tests supersede the
  profile before each transition.
- **Cancellation-journal failure bypassed awaited teardown**: the ward defer
  used the failure-marker preservation flag when it could not persist
  cancellation intent, so `Driver.Close` awaited a pipeline that returned
  while its credential-bearing writer and lease survived. Cancellation
  amendment failure now keeps the journal open but still reaps every runtime
  object and releases the lease; failure-marker preservation remains limited
  to an already absent writer whose marker must survive recovery.
- **Submission could retroactively claim a foreign run**: an explicit run ID
  naming a structurally compatible existing run caused submit to create the
  production ownership marker after accepting it. Existing-run replay now
  requires the exact marker, resolved policy, and artifact-bound invocation to
  pre-exist coherently; a new run must create all three lane objects in its own
  transaction and refuses orphaned pre-existing keys. Runtime ownership
  classification also strictly decodes and re-derives the marker payload
  instead of trusting its kind, and dispatch requires the artifact-bound
  invocation to name exactly the run's one specification rather than accepting
  arbitrary additional inputs. Submission authenticates both registered
  artifacts' semantic roles before creating the lane. Adversarial regressions
  cover the foreign run, orphan marker/invocation, malformed or retargeted
  marker, foreign specification, extra-input, and artifact-role-substitution
  shapes.
- **The resolved run policy is execution authority, not an audit label**:
  start and recovery now require the durable `paths` key to agree exactly
  with the manually configured Phase 1A.2 importer boundary, and import uses
  that authenticated list. This fails closed before the agent runs when a
  submitted policy is absent, broader, narrower, or digest-substituted.
- **Fresh submission omitted the notification capability key**: `submit`
  could create the SQLite store before daemon startup, after which the
  daemon correctly treated the missing sibling topic key as lost authority
  and refused to start. Submission now creates the key before a fresh store
  and refuses an existing store whose key is absent.
- **Allowed-path validation stopped before compiling the full glob**:
  production composition rejected obvious match-all prefixes but accepted
  malformed later segments that could strand a completed export in a
  permanently retrying import. The daemon now runs the importer's complete
  slash-glob validator before any writer starts.
- **Completed exports were journal-durable but host-volatile**: ward
  materialized the only replayable payload under the system temporary
  directory and closed its journal over that path. Verified outputs now land
  under a configuration-bound daemon state root, and their files and
  directory entries are synced before the completed close. The Claude driver
  authenticates the same configured root; the independent review caught and
  fixed its stale `/tmp` check, which otherwise rejected every successful
  production handoff after this move.
- **Repository imports could disappear or cross the snapshot boundary**:
  copying only `CLAUDE.md` left standalone `@AGENTS.md` pointers unresolved
  in the instruction-only volume. Composition v2 expands imports from the
  exact-base snapshot, rejects escapes, git metadata, cycles, non-regular
  paths, and every symlink component, and enforces one aggregate repository
  byte budget. The parent-symlink escape and stale export-root mismatch were
  additional P1s found by the independent pass, not the cited review lines.
- **The privilege drop hid the bundle from the writer it protects**: `cp -a`
  preserves the private 0600 mode of the host instruction snapshot, and the
  writer reads that bundle after `setpriv` drops it to UID 1001 from a mount
  it cannot chmod. Probed on the pinned image against Apple container: a
  0600 root-owned file under `/root/.claude` is unreadable at UID 1001 even
  with `/root` at 0711, and 0644 reads. The seeder now publishes the bundle
  world-readable inside the run-owned volume; the bundle is composed
  instructions, never credentials. Same probe confirmed setpriv with an
  empty bounding set launches and the pinned CLI runs at UID 1001. Every
  earlier claim that the non-root argv had been proven end to end was
  overstated: a real run would have failed on this read.
- **Fail-closed import resolution was a self-denial surface**: any line whose
  first character is `@` was treated as an instruction import, so a CSS
  at-rule, a decorator in a fenced example, or a handle anywhere in a managed
  repository's `CLAUDE.md` made composition, and therefore the run, fail. An
  import naming nothing readable in the snapshot now keeps its literal text,
  which is what the file already said; escapes, git metadata, symlinked
  components, cycles, and the byte budget stay fatal, because prose does not
  produce those shapes by accident.
- **Repository instructions followed the higher-priority host block**: all
  bytes shared one explicit system-prompt role, so a conflicting repository
  instruction was the later text despite the bundle claiming operator-host
  precedence. Repository blocks are now digest-delimited and path-scoped
  first, with the globally authoritative operator-host block last. The live
  gate's direct workspace and continuity conflicts confirmed that empirical
  precedence contract.
- Smaller: the started counter no longer drops a start whose dispatch mark
  failed; recovery interrupted by shutdown records canceled rather than
  failed; two comments that described behavior the code does not have were
  corrected.

**Confirmed and deferred** (filed as #377, not fixed here): the gate's
auth-store mutation observation (`HandoffResult.AuthStore`, including whether
the writer mutated its store inside the window) is produced and discarded by
the driver rather than recorded.

**Could not be refuted:** the shell quoting (fuzzed against `/bin/sh` with
embedded quotes, escapes, newlines, and command substitution); the mount
topology (the built spec passes ward's own validation, and the credential
target neither overlaps the instruction mount nor adds a second writable
mount); the scanner never echoing a match; host instruction edits being
unable to retarget an in-flight run; submit's digest handling and identity
collision behavior; and the evidence-before-export-before-result ordering.

**Accepted by decision, stated as posture:** the setup token is ambient only
inside the contained writer process tree; the rendered prompt still rides argv
into ward's durable journal, so an operator secret placed in a specification
or prompt package would be persisted there.

## Second Independent Pass: The Composition Was Never Exercised

The green suite proved every package and no composition. A refute-first pass
over the assembled lanes found one defect that made the unit's headline
capability impossible, plus a class of fail-closed verdicts that fail the
wrong thing.

- **The workspace seed fetched a repository with no working tree**, so every
  non-empty production run was refused before the writer started.
  `publish.Transport.FetchBase` deliberately materializes objects and refs
  without a checkout, a shape the import lane depends on and pins in a test;
  ward's observer proves the workspace's raw worktree against HEAD and
  therefore reads that shape as dirty, every tracked path missing. Both
  contracts were individually correct and individually tested. The seed lane
  now calls a second transport entry point that materializes the tree and
  writes the index into the checkout rather than the discarded scratch, so
  the writer's own `git status` is clean too; the import lane keeps the
  lighter shape, and a test pins each. Rejected: making `FetchBase` always
  materialize, which would hand the importer files nobody put there.
  The automated review then found the sibling instance the first sweep missed:
  `-run-conformance` builds its own `SeedBaseCheckout` from the same
  repository-only fetch, so the documented harness failed at daemon startup
  for the same reason. Enumerated mechanically rather than by eye: exactly two
  production sources construct a `SeedBaseCheckout` (the run seed and the
  conformance seed), both now materialize, and the publication lane's three
  fetches keep the light shape deliberately. The requirement now lives on
  `WorkspaceSeed.SourceDir`, the type that imposes it.
- **A configuration disagreement ended the daemon instead of holding the
  work.** The declared-path gate refused with a corruption-class error, which
  dispatch treats as fatal, which exits the reconcile loop, on every restart,
  taking the unrelated lanes with it. A policy carrying no `paths` key had no
  configuration that could ever release it. Path-boundary verdicts are now a
  mutable policy refusal the engine holds on (a reconfigured daemon resolves
  them without touching the recorded attempt), and submission refuses a policy
  with no enforceable boundary at the door. A digest substitution stays fatal:
  that one is corruption.
- **A pending production intent bricked any daemon composed without
  admission**, for the same reason. It now holds for a daemon that is
  configured for the lane.
- **Nested `.git` directories are ordinary repository content.** The walk
  skipped git metadata only at the repository root while expansion refuses a
  `.git` component at any depth and fails the whole composition, so a
  vendored checkout holding a `CLAUDE.md` made every run on that repository
  unstartable. Same class as the literal `@` lines above; the walk now skips
  git metadata at any depth.
- **Conformance stopped re-verifying the leased credential mount's read-only
  bit.** It is the one credential mount whose writability may legitimately be
  true, which makes it exactly the mount a construction bug could hand the
  writer read-write unchecked. Re-verified against the admitted lease.
- **Two security comments claimed more than the code holds**, and both are
  corrected in place rather than left to mislead a later change: the outcome
  marker's nonce authenticates freshness, not authorship (the writer shares a
  PID namespace and can read it from the launcher's cmdline; the root-owned
  0700 control directory inside a sticky evidence directory is the actual
  control), and the environment assertion covers the recorded container
  environment ward inspects, not the writer's own process environment, which
  does carry the token.
- **The operator harness could burn its full 2,400-second deadline on three
  distinct configuration mistakes** that are all indistinguishable from "not
  finished yet" while polling. An absent activated trust profile, a waiver
  repository id that disagrees with the repository id, and an inherited
  `FREESIDE_REAL_RUN_INVOCATION` now each fail before the daemon starts. The
  trust profile is checked, never recorded: activating one is the human
  approval unattended dispatch rests on.

## Marker Forgery, Re-Probed After The Privilege Drop

An earlier security note held that the outcome marker was forgeable: a
root-running tool could read the wrapper's nonce from `/proc/1/cmdline`, write
a zero-status marker, and kill the wrapper. Re-probed against the pinned image
under Apple container now that the writer is dropped to UID 1001, one half
survives and the other is closed.

- **The nonce is still readable.** `/proc/1/cmdline` is world-readable, the
  writer shares the launcher's PID namespace, and ward substitutes the nonce
  directly into that argv, so a probe at UID 1001 read a planted nonce off
  pid 1 verbatim. Nonce secrecy is not a property this design has.
- **Every step of the forge now fails.** At UID 1001, against the launcher's
  exact chown/chmod sequence: writing the marker, listing the control
  directory, removing it, renaming it aside, removing the evidence directory,
  and truncating the root-owned transcript are all denied; `kill -9 1` and
  killing any root process are denied; a setuid copy of `/bin/sh` does not
  return root under `--no-new-privs --bounding-set=-all`.
- **So the control moved, and the documentation had to follow.** The marker's
  integrity rests on the filesystem topology (a root-owned 0700 control
  directory inside the sticky 1777 evidence directory, written by a root
  wrapper the writer cannot signal), not on the nonce, which authenticates
  freshness alone. Two comments claiming otherwise are corrected in place.
- **That control had no test.** The whole property lives in one shell string
  that had only substring assertions on `setpriv` and the marker path, so an
  edit reordering the chown sweep past the control directory's creation, or
  relaxing either mode, would have removed the control silently.
  `TestAgentCommandKeepsTheOutcomeMarkerOutOfWriterReach` now pins the modes,
  the ownership, and the ordering against the drop; mutation-checked by
  relaxing the control directory to 0777 and confirming the failure.

## Commit Greenness: Three Commits Did Not Build

Bisect and per-commit review were both broken on this branch and nothing
noticed, because CI only ever builds the tip. Commits 2 through 4 failed to
compile and commit 4 additionally failed its tests, for two ordering defects
of the same shape: a consumer landing before the contract it consumes.

- **Symbols before their definitions.** The engine's production lane used
  `exec.ErrPreJobRefused`, `exec.ErrInputUnavailable`,
  `domain.ErrConformanceConfigurationUnbound`,
  `domain.ErrAdmissionConfigurationMismatch`, and
  `store.ReadTx.GetExecutionAdmissionRecord` three commits before the
  composition commit defined them. Each definition moved into the lane commit
  that first needs it, at its final position in the file so the later commits'
  trees are unchanged.
- **A migration numbering gap.** The stage-driver commit added `0021` and
  `0022` while the composition commit added `0020`, so the loader's
  contiguity check failed every store-opening test at that commit. `0020`
  moved to the commit that introduces `0021`.
- **The tip's tree is byte-identical to before the pass** (`git diff` between
  the two tips is empty), so nothing in the reviewed content changed; only
  which commit carries it. All six commits now pass `go build`, `go vet`, and
  `go test ./...` independently.

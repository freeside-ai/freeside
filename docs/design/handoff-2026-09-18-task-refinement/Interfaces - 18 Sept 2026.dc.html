Assessment · main as of 2026-09-18 · 11:30
Six days: the task becomes the unit

Row 4 of the 12 Sept canvas is built: the menu-bar panel (M1), the segmented controls and trailing summary values (M2), the consequence sheet (C1), and sheet chrome (S1) are all on main. The larger change is structural — the Runs section is gone and a Tasks section owns runs, submission, and stopping.

Landed
  • Tasks list replaces Runs (#1174 → #1374). One row per task: name, meta line, then wrapping title-case status and per-phase text — no rail dots, no color needed to read progress. Active · Finished · All.
  • Task identity (#1346, #1347, #1208). Every task has a display name: operator-chosen, agent-proposed (carries the AGENT keyword as a labeled claim), or the id in mono. It appears on rows, the timeline header, the run timeline's eyebrow, and the inbox context line.
  • New task composer (#1366) on the Tasks toolbar, ⌘N: project trigger, source, optional name, Cancel / Submit. Never retries.
  • Unconfirmed submissions — a separate read-only recovery sheet with per-request Retry. Opening never sends.
  • Task timeline (#1372, #1373): campaign sections newest first, run cards titled by attempt with Review above run details, then Task Events — the reconstructed whole-task history.
  • Stop (#1344, #1368, #1369): task-level Stop with confirmation; requested → confirmed / failed-to-stop as daemon facts; a durable Stop ledger and a Pending Stops toolbar action.
  • Run timeline eyebrow now names the task; it is reached only through its task or a launch link.
  • Technical details (#1379, midday). Exact ids leave the primary views. The task header, each campaign section, and each run card end in a collapsed Technical details disclosure — value under its label, copy control trailing, unchanged from the daemon. The eyebrow is a bare TASK TIMELINE; parent and superseding runs are named by role and attempt; event lines read "Implementation attempt 2 · Round 3 · Head …" and a second campaign shows a short id only when two are on screen. A Tasks row appends a short id to its meta line only when another visible row shares its name, and macOS drops the system selection fill so bar + wash is the only selection.
Seams (row 3 specifies)
  • TaskStopView and its confirmation and Pending Stops sheets are plain SwiftUI text and buttons — no keyword header, no ConsequenceSheet, a "Keep task" that is not a sheet footer.
  • Toolbar recovery actions are bare titled buttons: "Unconfirmed (1)", "Pending Stops (1)".
  • An over-long task name fails with a bare status-400 message; the composer has no 60-character guard.
Still not built

effect_proposal · attachment upload · evidence packet viewer · proposal batches · initiative view · push · device list · retry-with-profile (#921) · severity scale · fault-class capture · historical cancellation enumeration (#1397).
